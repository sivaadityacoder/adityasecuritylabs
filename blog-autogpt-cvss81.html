CVE-2026-22038 CVSS 8.1 HIGH August 2026 · Siva Aditya Panuganti

How I Found CVSS 8.1 in AutoGPT:
API Keys in Logs

AutoGPT was writing OpenAI API keys to stdout in plaintext. Every single run. One log aggregator, one misconfigured CloudWatch policy, one junior DevOps engineer — and a company's entire OpenAI billing account is compromised. This is CVE-2026-22038, CVSS 8.1.

What AutoGPT Does

AutoGPT Stagehand is an agentic framework for orchestrating multi-step LLM tasks. It manages API calls, memory, tool use, and task planning in autonomous loops. At scale, it processes hundreds of LLM calls per session — each one authenticated with an API key passed through the execution context.

Where the Vulnerability Was

The problem was in the logging subsystem. During agent initialization and tool execution, AutoGPT called logger.info() with the full configuration object — including the API key — without sanitizing sensitive fields first.

# Vulnerable pattern (simplified)
logger.info(f"Agent initialized with config: {agent_config}")
# agent_config contained: {"openai_api_key": "sk-proj-...", ...}

The key was never explicitly logged. It leaked because the config dict was passed directly to the logger as a format argument. In production environments with structured logging (Datadog, CloudWatch, Splunk), this meant API keys appeared in log streams visible to anyone with read access to the logging service.

How I Found It

I wasn't fuzzing. I was doing a source code review looking for secret handling patterns. My tool, ASL V6, builds an AST of the codebase and traces data flow from environment variable reads to output sinks — print statements, logging calls, HTTP responses.

It flagged logger.info calls where the argument included variables derived from os.getenv("OPENAI_API_KEY"). Manual confirmation took 15 minutes. The key was there, in the log, every time the agent started.

The CVSS 8.1 Impact

High. No authentication required to exploit — just access to the log stream, which in most organizations is shared infrastructure. An attacker reads the logs, extracts the key, and can make unlimited OpenAI API calls billed to the victim. In enterprise deployments with high-volume agent usage, this translates directly to financial damage.

The Fix

Patched in AutoGPT v0.6.46. The fix sanitizes configuration dictionaries before logging by redacting fields that match a secret key pattern (*key*, *token*, *secret*, *password*).

Check this in your own codebase right now

Run this in your repo to find any logger calls that might be passing config objects with secrets:

grep -rn "logger\.\(info\|debug\|warning\)" . | grep -i "config\|key\|token\|secret"

If you get results — open each one and verify the logged object doesn't contain sensitive fields. This takes 20 minutes and costs nothing.

If you're running an AI agent framework and haven't audited your logging pipeline, this is the first place to look. It's not glamorous. But it's where the real breaches start.
